# Newsletter Playbook

This project can become either an internal research briefing or a public
newsletter. The shape is similar, but the editorial bar is different.

## Product Options

### Internal Desk Update

Best for speed and usefulness:

- publish once or twice a day
- include more items
- optimize for coverage, not polish
- keep all links and abstracts

### Public Newsletter

Best for audience growth:

- publish on a predictable cadence
- include fewer papers
- add stronger editorial voice
- explain why each item matters in plain English

## Recommended Editorial Stack

1. Machine pass
   Poll, dedupe, rank, and summarize.

2. Editor pass
   Rewrite the top 3-5 “why it matters” blurbs.

3. Distribution
   Publish to:
   - Beehiiv
   - Substack
   - Ghost
   - Slack
   - Telegram

## Strong Newsletter Positions

Start narrow before going broad:

- Market microstructure
- Execution and TCA
- Crypto market structure
- LLMs in finance
- Factor research

Focused positioning beats “all quant papers” early on.

## Suggested Sections

- `Top Reads`
- `Alpha / Forecasting`
- `Execution / Microstructure`
- `Risk / Market Structure`
- `One Paper To Actually Read`

## Best Near-Term Product Plan

1. Keep this repo as the monitor + digest engine.
2. Publish markdown first.
3. Add one delivery target, ideally email or Telegram.
4. Only then add deeper extraction and retrieval.

## Delivery Notes

This repo now includes lightweight delivery hooks for:

- Telegram bot delivery
- SMTP email delivery

Use them for internal distribution first, then add a stronger publication layer
for public newsletter workflows.
